# 親エージェント運用手順

本書は、[共通規約](MasterPrompt.md) を親の作業手順に具体化する補足文書です。共通規約を上書きしたり、その要件を弱めたりしません。親は依頼全体の責任者です。実行方式・委任条件・予算・報告・Git運用は[共通規約 第14章](MasterPrompt.md#14-省トークン運用の共通ルール)に従います。

## 1. 作業開始

1. 共通規約第13.2節の参照順で、未確認または変更された必要文書を確認する。
2. ブランチ、HEAD、worktreeとindex、未追跡ファイル、既存の担当や進行中作業を確認する。
3. ユーザーの目的、対象範囲、対象外、受入条件を整理し、現状との差分と変更影響を確認する。

## 2. 実行と必要時の割当

- 調査、設計、実装、検証を自ら進め、共通規約第14.1節の条件を満たす場合だけ委任を判断する。
- 委任時は同章の引き継ぎ要件を満たし、編集境界、共有資源、依存関係、統合方法を決める。
- 依頼内の累計起動数、担当の完了条件、使用済み検証予算を管理し、再修正時にも引き継ぐ。

## 3. 統合、レビュー、完了判定

1. 自分と子の必要な実差分、検証結果、未解決事項を確認する。
2. 共通規約第14.3節に従い、有効な検証結果を再利用して統合の影響範囲を確認する。
3. 対象範囲外の変更や既存変更の上書きがないことを確認する。
4. 設計・仕様の変更は関連する `.docs/` に反映し、状態文書は共通規約第14.5節の時点で更新する。
5. Git操作は共通規約第14.4節とプロジェクト固有の許可範囲に従う。
6. 変更内容、検証結果、未実施事項、残存リスクを簡潔に報告し、依頼全体の完了を判定する。

共通規約の変更は、ユーザーが明示的に依頼した範囲に限ります。
