## 1. 目的、対象範囲、結論

本書は、Music DL の現行実装を基準に、システム境界、構成、責務、処理フロー、データ、計算、エラー処理、制約を説明します。開発者、レビュー担当者、運用担当者を対象とします。要求の基準は[プロジェクト概要](ProjectContext.md)、導入・操作・障害対応は[使い方ガイド](Usage.md)を参照してください。

Music DL は、画面、取得・変換、設定、入力検証を分離した小規模なレイヤード構成です。レイヤード構成とは、役割ごとにプログラムを層へ分け、変更の影響を狭くする設計です。サーバー、データベース、利用者認証は持ちません。

設計上の重要な原則は次のとおりです。

1. 画面に `yt-dlp` や FFmpeg 固有の処理を持たせない。
2. URL、保存先、設定、外部プログラムを信頼せず、境界で検証する。
3. 取得・変換はバックグラウンドスレッドで実行し、画面部品は画面側のスレッドだけで更新する。
4. 実行状態の所有者を `DownloadService` に限定し、二重実行を防ぐ。
5. 設定は検証済みの不変データとして扱い、保存途中の破損を抑える。

主要構造は実装済みで、単体テストと静的検査は成功しています。ただし、外部サービスとの自動結合試験と GUI 自動試験は未実装であり、URL 検証は単一動画を厳密に識別できない場合があります。

## 2. システム境界と依存関係

```text
利用者
  │ URL、音声ビットレート、保存先フォルダ
  ▼
Music DL デスクトップアプリケーション
  ├── YouTube ──────── 音声と動画情報の取得元
  ├── yt-dlp ───────── 取得処理と FFmpeg 後処理の制御
  ├── FFmpeg ───────── MP3 への変換
  ├── 保存先フォルダ ── 完成した MP3 と部分ファイル
  └── settings.json ── 保存先と音声ビットレート
```

| 境界 | 入力 | 出力 | 検証・制御 | 主な障害 |
| --- | --- | --- | --- | --- |
| 利用者入力 | URL、保存先、音声ビットレート | 検証済み値またはエラー | URL 形式、プレイリスト、フォルダの存在・種別・書き込み可否、許可ビットレート | 空値、対象外 URL、無効な保存先 |
| YouTube | 検証後の URL と通常の通信情報 | 音声、動画情報、外部エラー | `yt-dlp` を介して接続 | 非公開、地域制限、仕様変更、通信障害、レート制限 |
| `yt-dlp` | 取得・変換オプション | 進捗、動画情報、エラー | サービス層でオプションを固定 | 互換性変更、取得失敗、部分ファイル |
| FFmpeg | 取得済み音声、MP3 設定 | MP3 または変換エラー | 起動時と処理開始時に PATH 上の存在を確認 | 未導入、PATH 未設定、変換失敗 |
| ファイルシステム | 設定、MP3、部分ファイル | 永続ファイルまたは I/O エラー | 設定の一時ファイル保存と置換 | 権限不足、容量不足、破損、同名ファイル |

PATH は Windows が実行プログラムを探すフォルダの一覧です。設定の「置換」は、完成した一時ファイルを `settings.json` へ入れ替え、途中まで書かれた設定が残る可能性を下げる方法です。

## 3. 構成、責務、依存方向

### 3.1. 起動境界

| 要素 | 責務 | 依存先 |
| --- | --- | --- |
| `run.ps1` | Python Launcher と FFmpeg の確認、`.venv` の作成、必要時のパッケージ導入、アプリケーション起動 | `py`、FFmpeg、`requirements.txt` |
| `src/main.py` | `ModernUI` の生成と GUI イベントループの開始 | `src/ui/app_window.py` |

`run.ps1` は `.venv` が存在すれば再利用します。また、`customtkinter` と `yt_dlp` を読み込める場合は `requirements.txt` の固定バージョンとの差異を検査しません。デスクトップショートカットは利用者環境にだけ存在し、リポジトリでは管理しません。

### 3.2. プレゼンテーション層

`src/ui` は GUI の表示と利用者操作を担当します。

- `app_window.py` の `ModernUI` は、URL 入力、設定変更、処理開始、進捗、結果、画面内ログを管理する。
- `theme.py` の `Theme` は、色、フォント、角丸などの表示値を一元管理する。
- ワーカースレッドからの通知は `queue.Queue` に入れ、画面側が 50 ミリ秒間隔で取り出す。
- 取得中は URL、貼り付け、保存先、音声ビットレート、開始ボタンを無効にする。
- Enter キーで開始し、Ctrl+L キーで URL 入力欄へ移動する。

### 3.3. コア層

`src/core` は GUI から独立した処理を担当します。

| モジュール | 主な公開要素 | 責務 |
| --- | --- | --- |
| `download_service.py` | `DownloadService` | FFmpeg の確認、`yt-dlp` オプション、ワーカースレッド、通知、単一実行の制御 |
| `config.py` | `AppConfig`、`ConfigManager` | 設定値の検証・保持、`settings.json` の読み込みと置換保存 |
| `validation.py` | `validate_youtube_url()`、`validate_output_directory()` | 利用者入力の検証と正規化 |

依存方向は、起動境界からプレゼンテーション層、プレゼンテーション層からコア層です。コア層は GUI 部品を直接参照せず、コールバック関数で通知します。

## 4. 起動、設定、画面状態のフロー

### 4.1. 起動と設定読み込み

1. `run.ps1` が `py` と FFmpeg を PATH から探す。見つからない場合は英語のエラーを出して終了する。
2. `.venv\Scripts\python.exe` がなければ、`py -3.14 -m venv .venv` で仮想環境を作る。
3. `customtkinter` または `yt_dlp` を読み込めなければ、`requirements.txt` からパッケージを導入する。
4. プロジェクトルートへ移動し、`.venv\Scripts\python.exe -m src.main` を実行する。
5. `ModernUI` が `ConfigManager.load()` で `settings.json` を読む。
6. ファイルがない場合、または JSON、型、値が不正な場合は、保存先を利用者の `Downloads`、音声ビットレートを 192 kbps にする。不正時は画面内ログへ警告する。
7. `DownloadService.validate_environment()` が FFmpeg を確認する。見つからない場合は開始ボタンを無効にする。

### 4.2. 設定更新

1. 利用者が保存先または音声ビットレートを変更する。
2. `AppConfig.with_save_dir()` または `with_bitrate()` が新しい不変オブジェクトを作る。
3. `ConfigManager.save()` が UTF-8 の `settings.json.tmp` を書き、フラッシュと `fsync` の後に `settings.json` へ置換する。
4. 保存に失敗した場合は一時ファイルを可能な範囲で削除し、`ConfigurationError` を画面へ返す。画面上の現在設定は更新しない。

保存先の変更時点では、存在と書き込み可否を検証しません。処理開始時に `validate_output_directory()` が検証するため、設定保存の成功は、その保存先で取得できることを意味しません。

### 4.3. 画面状態

| 状態 | 状態表示 | 進捗 | 操作 |
| --- | --- | --- | --- |
| 待機 | `READY` | 0 | 入力と設定変更が可能 |
| 処理中 | `WORKING` | 0.0 から 0.95 | 入力と設定変更を無効化 |
| 成功 | `DONE` | 1.0 | URL を空にして次の処理が可能 |
| 警告 | `CHECK` | 直前値 | 内容に応じて利用者の修正を待つ |
| 失敗 | `ERROR` | 0 | 詳細ログを自動表示し、再操作を可能にする |

## 5. 取得・変換フローと並行処理

1. 画面が URL を検証し、`DownloadService.run_download()` が URL、保存先、FFmpeg を再検証する。
2. `threading.Lock` の保護下で `_is_running` を確認する。既に実行中なら `False` を返す。
3. 実行枠を取得した場合、`music-dl-worker` というデーモンスレッドを開始する。
4. サービスが `yt-dlp` のオプションを組み立て、最良の利用可能な音声を取得する。
5. 進捗フックが取得率と推定残り時間をコールバックへ渡す。取得完了時は進捗 0.95 と変換中表示を渡す。
6. `yt-dlp` の後処理が FFmpeg を呼び、選択した音声ビットレートの MP3 へ変換する。
7. 成功時は安全化した動画タイトルをログへ渡し、完了を通知する。失敗時は URL を `[URL]` へ置換した最大 300 文字の概要を通知する。
8. 成否にかかわらず `_is_running` を解除し、完了コールバックで画面操作を戻す。

デーモンスレッドは、アプリケーション終了時に完了を待たず終了できるスレッドです。取得中の終了では確認画面を出しますが、利用者が終了を選んだ後の変換完了や部分ファイルの整理は保証しません。キャンセル専用の制御は未実装です。

画面部品はスレッド安全ではないため、ワーカースレッドが直接更新しません。ワーカーのコールバックは `_post_ui()` を通じてキューへ積まれ、画面スレッドの `_drain_ui_queue()` が処理します。

## 6. データ構造、スキーマ、計算ロジック

### 6.1. `AppConfig` と `settings.json`

`AppConfig` は変更不能なデータクラスです。JSON のルートはオブジェクトである必要があります。

| JSON 項目 | Python 型 | 必須性 | 許可値・既定値 | 用途と制約 |
| --- | --- | --- | --- | --- |
| `save_dir` | 文字列 | 任意 | 未指定時は `<利用者ホーム>\Downloads` | 空白だけは不可。`~` を利用者ホームへ展開する。存在と書き込み可否は取得開始時に検証する |
| `bitrate` | 文字列 | 任意 | `128`、`192`、`320`。既定値は `192` | FFmpeg の `preferredquality` へ渡す。数値型は受け付けない |

```json
{
  "save_dir": "C:\\Users\\user\\Downloads",
  "bitrate": "192"
}
```

未知の JSON 項目は読み込み時に無視されます。JSON 解析、ルート型、項目型、許可値、ファイル読み込みのいずれかに失敗すると、項目単位ではなく設定全体を既定値へ戻します。

### 6.2. `yt-dlp` オプション

| 項目 | 値 | 役割 |
| --- | --- | --- |
| `format` | `bestaudio/best` | 利用可能な最良音声を優先し、なければ最良形式を使う |
| `outtmpl` | `<保存先>/%(title)s.%(ext)s` | 動画タイトルを基に一時出力名を作る |
| `noplaylist` | `True` | プレイリスト取得を無効にする |
| `postprocessors` | `FFmpegExtractAudio`、MP3、選択ビットレート | FFmpeg で MP3 へ変換する |
| `socket_timeout` | 30 | 通信待ちのタイムアウトを 30 秒にする |
| `retries` | 3 | 通常取得の再試行回数を 3 回にする |
| `fragment_retries` | 3 | 分割データ取得の再試行回数を 3 回にする |
| `quiet`、`no_warnings` | `True` | `yt-dlp` の標準表示を抑え、アプリケーションの通知へ集約する |

### 6.3. 進捗計算

取得済みバイト数を `D`、総バイト数または推定総バイト数を `T` とすると、`T > 0` の場合の画面進捗 `P` は次式です。

```text
P = max(0.0, min(D / T, 0.94))
```

バイト数を使えない場合は、`yt-dlp` の進捗文字列から最初の数値を読み、100 で割って同じ 0.00 から 0.94 の範囲に収めます。どちらも使えない場合は 0.0 です。取得完了時は 0.95、全処理成功時は画面側で 1.0 にします。この値は処理時間の割合ではなく、取得データ量を基にした目安です。

### 6.4. コールバックと状態

| インターフェース | 入力 | 出力・副作用 |
| --- | --- | --- |
| 進捗コールバック | `float` の進捗、表示文 | 画面キューへ進捗更新を登録 |
| ログコールバック | メッセージ、`info`・`success`・`warning`・`error` の水準 | 画面キューへログ追加を登録 |
| 完了コールバック | 成否、表示文 | 画面キューへ終了処理を登録 |

取得の実行中状態は `DownloadService` が所有し、ロックで読み書きを保護します。画面状態は `ModernUI`、永続設定は `ConfigManager` が所有します。

## 7. 検証、例外、セキュリティ

### 7.1. 入力検証

- URL の前後空白を除去し、HTTP または HTTPS、YouTube または `youtu.be` のホストに限定する。
- `list` クエリーパラメーターを含む URL をプレイリストとして拒否する。
- `/watch` 形式では `v` パラメーターを必須とし、その他はパスが空でなければ受理する。
- 保存先は存在するフォルダで、`os.access(..., os.W_OK)` が書き込み可能と判定する必要がある。
- 音声ビットレートは文字列の `128`、`192`、`320` に限定する。

URL 検証の3項目目は、要件上の「単一動画」より許容範囲が広く、動画以外の YouTube ページを通す可能性があります。現行仕様へ読み替えず、[プロジェクト概要](ProjectContext.md)の実装差異として管理します。

### 7.2. 例外と利用者への通知

| 発生箇所 | 例外・条件 | 動作 |
| --- | --- | --- |
| URL・保存先 | `InputValidationError` | 取得を開始せず、状態表示へ理由を出す |
| FFmpeg | 見つからない | 起動時は開始ボタンを無効化、開始時は `RuntimeError` |
| 設定読み込み | I/O、JSON、型、値の異常 | 既定値へ戻し、画面内ログへ警告 |
| 設定保存 | I/O 異常 | 一時ファイルを可能な範囲で削除し、`ConfigurationError` を表示 |
| 取得・変換 | すべての `Exception` | URL を置換した概要をログへ出し、一般的な失敗文を表示 |
| スレッド開始 | `RuntimeError` | 実行中状態を解除して例外を呼び出し元へ返す |

### 7.3. セキュリティとプライバシー

- API キー、パスワード、Cookie、個人情報を設定として保存しない。
- 独自の利用分析情報を送信しない。ただし、取得時は YouTube など接続先へ URL と通常の通信情報が送られる。
- エラー文字列中の HTTP・HTTPS URL を `[URL]` へ置換し、空白を正規化して 300 文字まで表示する。
- 成功ログの動画タイトルは表示可能な文字だけに限定し、100 文字まで表示する。
- 画面ログはメモリ内だけに保持し、終了時に消える。URL 以外のファイル名や環境情報が含まれる可能性は残る。
- コンテンツの権利確認、利用許諾、DRM 回避防止を技術的には判定しない。

## 9. 設計判断、リスク、関連文書

| 採用判断 | 理由 | 代替案とトレードオフ |
| --- | --- | --- |
| 小規模なレイヤード構成 | 画面と外部処理を分離し、単体テストしやすい | 単一ファイルは短いが、変更の影響が広がる |
| `yt-dlp` をサービス層で包む | GUI を取得方法から分離できる | GUI から直接呼ぶとコードは減るが結合が強くなる |
| 標準 JSON とデータクラス | 現規模で依存を増やさず検証と保存ができる | Pydantic は複雑な検証とスキーマ生成に向くが依存が増える |
| スレッドと画面キュー | 同期式の取得処理と GUI イベントを分離できる | `asyncio` は全面的な非同期設計と GUI 統合が必要になる |
| FFmpeg の外部導入 | 実績のある変換機能を利用し、配布物を小さくできる | 同梱は導入を簡単にできるが、容量、更新、ライセンス管理が増える |

優先して判断が必要な事項は、URL 形式の厳密化、部分ファイルとキャンセルの規則、依存バージョン確認方法、利用者別設定領域への移行です。変更時は既存インターフェース、設定形式、利用者データへの影響を先に評価します。
