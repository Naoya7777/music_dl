# music_dl の検証標準

新規Workでは対象の意味に合う受入条件を事前に定義する。既存のProject規約、固定Gate、承認、保護資産の条件を適用する。

1. Git HEAD、原本、署名、承認範囲について、対象ごとに要求されるSHA・署名・承認範囲をそれぞれ照合する。
2. 構成・契約・データは安定したキーで比較し、追加・削除・変更、静的構成・動的観測を記録する。許可された変更と、独立証拠で説明できる動的差分を明示する。重要な不明・想定外差分はBLOCKED、改ざんや不変条件違反はFAILとして扱う。
3. 許可と拒否の両方を試験する。権限分離の判定が必要な場合はControllerとWorkerそれぞれの実効権限を再現し、正負canaryを実施して、欠測・未実施・合成・実環境の結果を区別する。
4. Evidenceに対象SHA、環境、主体、時刻、差分、理由、Review・CI、未検証範囲を記録する。非公開の原本は保全する。

## このProjectでの適用

ファイル形式、メタデータ、変換エラーをローカルfixtureで検証する。実ネットワーク、外部サービス、ダウンロードの確認は既存の条件に従う。

導入範囲は検証設計の文書。実行Gate、CI、稼働環境の変更は個別Workで検証する。
