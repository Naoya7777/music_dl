# Music DL UI設計書

文書版数: 3.0 / 更新日: 2026-10-25 / 確認基準Git: `95c2ec0d9b289f8548d990d1feb882462ce7f0e0` / 検証区分: 静的確認のみ（製品・正式Gate未実行）


目的は、一画面の入力、処理中制御、成否と補助dialogを安定IDで追えるようにすることである。

## 1. 画面・操作一覧

| ID | 目的・到達 | 表示/入力・操作・遷移 | 要件 |
| --- | --- | --- | --- |
| UI-001 | 起動時のメイン画面 | URL欄、貼付、MP3をダウンロード、進捗、保存先、音質。Enterで開始、Ctrl+LでURL選択 | FR-01/02/03/06/07/10 |
| UI-002 | メインの保存先操作 | folder dialogで選択、設定保存成功時だけ表示更新。cancelは変更なし | FR-04/05 |
| UI-003 | メインの詳細ログ | 表示/非表示切替。時刻、水準、メッセージ。errorログで自動展開 | FR-06、NFR-08 |
| UI-004 | 処理中のウィンドウ終了 | 確認dialog。いいえで継続、はいでdestroy | 終了時制約、cancel機能ではない |

これらは文書追跡IDで実装のwindow IDではない。外観の実機確認はしていない。`src/ui/app_window.py: ModernUI` が根拠。

## 2. レイアウト・共通部品

Dark、初期760×720、最小700×660。header、download card、status card、保存先/音質、log panelの縦構成。log展開時760×860へ変更する。見た目のfont/色は `src/ui/theme.py` のThemeを正本とし、ピクセルの実表示やDPI適合は未検証。

## 3. 入力検証と結果

URLは空白除去、HTTP/HTTPS、YouTube系host、非空path、watchならvを検証しlistを拒否。ただし単一動画を厳密に限定しない既知差異を維持する。音質は128k/192k/320kを表示し文字列bitrateへ変換。保存先は設定時には構造のみ、開始時に空値・存在・directory・os.access(W_OK)を確認する。保存失敗時は元の設定・音質表示を保持する。

## 4. 状態・アクセシビリティ

| 状態 | 表示・操作 |
| --- | --- |
| 初期/待機 | READY、入力を促す、進捗0 |
| 準備/取得/変換中 | WORKING。URL/貼付/保存先/音質/開始を無効化。進捗0〜0.94、取得完了0.95 |
| 成功 | DONE、進捗1、URLを消し操作再有効化 |
| warning | CHECK、clipboard取得失敗等の説明 |
| 入力・環境エラー | ERROR、開始前に理由。FFmpeg起動時不在は開始無効 |
| worker失敗 | ERROR、進捗0、操作復帰。errorログを展開 |
| データなし・権限不足 | 独立画面なし。保存先権限などは入力/処理errorへ集約 |

進捗・状態文・badgeはコード確認のみ。UI queueは50msごとのafterで排出しworkerから直接widgetを操作しない。色と文字の併用、一部shortcutは実装あり。読み上げ、keyboard全域、contrast、DPI、GUI応答性の実測は未確認、適合基準は未決定。手動受入は[Usage§9](UI_design.md#h-4ee2d5493e7b)。

#### 1. 目的、対象範囲、結論


本書は、Windows で Music DL を導入、起動、操作し、問題を切り分ける方法を説明します。主な対象は利用者と導入・運用担当者です。内部実装を変更する手順は対象外です。

準備済みの環境では、プロジェクトルートで次のコマンドを一回実行すれば起動できます。

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

起動後は、YouTube の単一動画 URL を入力し、音声ビットレートと保存先フォルダを確認して「MP3をダウンロード」を選びます。処理できるのは、利用者が保存する権利または許諾を持つコンテンツだけです。

重要な原則は次のとおりです。

1. 対象コンテンツの権利、利用許諾、YouTube の利用規約、適用法令を利用者自身で確認する。
2. Python、FFmpeg、インターネット、保存先の権限と空き容量を事前に確認する。
3. 処理中にアプリケーションを終了せず、完了または失敗の表示を待つ。
4. 問題が起きた場合は、状態表示と詳細ログを確認してから環境と入力を切り分ける。

サービスの目的、要件、実装状況は[プロジェクト概要](ProjectContext.md)、内部構造とデータは[アーキテクチャ](Architecture.md)を参照してください。

#### 2. 利用条件と用語


<a id="h-3ef44e6ad49c"></a>
##### 2.1. 必要な環境

| 項目 | 条件 | 確認方法 |
| --- | --- | --- |
| OS | Windows | Windows の設定で確認する |
| Python | Python 3.14 と Python Launcher の `py` コマンド | `py -3.14 --version` |
| FFmpeg | `ffmpeg` コマンドを PATH から実行できる | `ffmpeg -version` |

##### 2.2. 権利と利用条件

対象コンテンツを保存する権利または必要な許諾があることを、利用者自身で確認してください。個人利用、YouTube の利用規約、著作権法、その他の適用法令の範囲で使用し、無断複製やデジタル著作権管理（DRM）の回避に使用しないでください。Music DL は権利確認や許諾取得を代行しません。

#### 3. 導入と環境準備


<a id="h-7d7b4a64ad72"></a>
##### 3.1. 自動準備を使う

Python 3.14 と FFmpeg を導入した後、プロジェクトルートで次を実行します。

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

`run.ps1` は次の順序で処理します。

1. `py` コマンドと FFmpeg が PATH から使えるか確認する。
2. `.venv\Scripts\python.exe` がなければ Python 3.14 で仮想環境を作る。
3. `customtkinter` または `yt_dlp` を読み込めなければ、`requirements.txt` から依存パッケージを導入する。
4. プロジェクトルートを作業フォルダとして Music DL を起動する。

`-ExecutionPolicy Bypass` は、この一回の PowerShell 実行に限ってスクリプトの実行を許可する指定です。Windows 全体の実行ポリシーは変更しません。

既存の `.venv` がある場合、`run.ps1` は Python の版を再確認しません。また、必要なモジュールを読み込める場合、`requirements.txt` の固定バージョンと一致するかを確認しません。環境更新後に問題がある場合は、運用担当者が仮想環境と依存バージョンを確認してください。

<a id="h-e99abcfb00ac"></a>
##### 3.2. 手動で準備する

自動準備を使わない場合は、プロジェクトルートで次を実行します。

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

FFmpeg は信頼できる配布元から導入し、`ffmpeg.exe` のあるフォルダを PATH に追加します。新しい PowerShell を開き、次が成功することを確認します。

```powershell
ffmpeg -version
```

#### 5. 基本操作と画面状態


<a id="h-40a66b049f8f"></a>
##### 5.1. MP3 を保存する

1. YouTube の単一動画 URL を入力する。「貼り付け」ボタンも使用できる。
2. 音声ビットレートを 128k、192k、320k から選ぶ。初期値は 192k である。
3. 「保存先」を選び、出力フォルダを指定する。初期値は利用者の `Downloads` である。
4. 「MP3をダウンロード」を選ぶ。Enter キーでも開始できる。
5. 状態表示、進捗バー、必要に応じて詳細ログを確認する。
6. 「MP3 の保存が完了しました」と表示されたら、保存先で MP3 を確認し、再生する。

画面上の `k` は kbps を表します。値が大きいほど一般にファイル容量も増えますが、元の音声を超える品質にはなりません。

<a id="h-7062a2eab13b"></a>
##### 5.2. 状態表示

| 表示 | 意味 | 利用者の対応 |
| --- | --- | --- |
| `READY` | 入力待ち | URL と設定を確認して開始する |
| `WORKING` | 取得または変換中 | 完了または失敗まで待つ |
| `DONE` | MP3 の保存完了 | 保存先と再生結果を確認する |
| `CHECK` | 利用者の確認が必要 | 表示内容を確認して入力や環境を修正する |
| `ERROR` | 開始前検証、取得、変換、設定保存の失敗 | 詳細ログと本書の障害対応を確認する |

処理中は URL、貼り付け、音声ビットレート、保存先、開始ボタンを操作できません。成功後は URL 欄が空に戻り、次の一件を開始できます。Ctrl+L キーで URL 入力欄へ移動できます。

進捗は取得データ量を基にした目安です。変換中は 95% と表示され、処理時間の95%が完了したことを意味しません。


<a id="h-df40615e1753"></a>
#### 6. 設定、ログ、出力データ


<a id="h-290eebc4940f"></a>
##### 6.1. 設定ファイル

保存先フォルダと音声ビットレートは `settings.json` に UTF-8 で保存され、次回起動時に復元されます。`run.ps1` から起動した場合はプロジェクトルートに作られます。

```json
{
  "save_dir": "C:\\Users\\user\\Downloads",
  "bitrate": "192"
}
```

| 項目 | 型 | 許可値 | 省略時 |
| --- | --- | --- | --- |
| `save_dir` | 文字列 | 空白だけでないフォルダパス | 利用者の `Downloads` |
| `bitrate` | 文字列 | `128`、`192`、`320` | `192` |

このファイルへ秘密情報を書かないでください。JSON、項目型、値、読み込みのいずれかに問題がある場合は設定全体が既定値へ戻り、詳細ログに警告が表示されます。保存先の存在と書き込み可否は MP3 の処理開始時に検証されます。

手動で初期化する場合は、アプリケーションを終了し、`settings.json` を別名で退避してから再起動します。退避したファイルから設定は自動復元されません。

<a id="h-66b81428d6dc"></a>
##### 6.2. 詳細ログ

「詳細ログを表示」を選ぶと、環境確認、設定変更、処理開始、完了、失敗を確認できます。ログは画面内だけにあり、ファイルには保存されず、アプリケーション終了時に消えます。

エラー中の HTTP または HTTPS の URL は `[URL]` に置き換えて表示します。ただし、動画タイトル、ファイル名、環境情報が含まれる可能性があるため、問い合わせや画面共有の前に公開してよい内容か確認してください。

<a id="h-6335d67e5b0e"></a>
##### 6.3. MP3 と部分ファイル

MP3 は画面で指定した保存先フォルダへ出力されます。ファイル名は動画タイトルを基に `yt-dlp` が作ります。Windows で使えない文字の変換、同名ファイル、失敗時の部分ファイルの扱いには Music DL 独自の規則がなく、`yt-dlp` の動作に従います。


<a id="h-9ed796af4d3a"></a>
#### 7. 制約、安全性、運用上の注意


- 一回に処理できる URL は一件である。
- YouTube の単一動画を対象とし、`list` パラメーターを含むプレイリストと YouTube 以外の URL は拒否する。
- 現行の URL 検証は、YouTube ドメイン上の動画以外の一部 URL を処理開始まで通す可能性がある。その場合は取得段階で失敗し得る。
- 出力形式は MP3 だけである。
- 一時停止、再開、キャンセル、履歴管理はない。
- 取得可否は、動画の公開状態、地域制限、ネットワーク、YouTube、`yt-dlp`、FFmpeg に依存する。
- 通信タイムアウトは 30 秒で、通常取得と分割データ取得の再試行回数は各 3 回である。
- 取得中に終了すると、処理完了と部分ファイルの整理を保証できない。
- 保存先の空き容量を処理前に自動確認しない。
- 永続ログ、利用状況の計測、遠隔監視、警告通知、自動復旧はない。
- API キー、パスワード、Cookie は保存しない。独自の利用分析情報は送信しないが、取得時には接続先へ URL と通常の通信情報が送られる。


<a id="h-0d23520c1a37"></a>
#### 8. トラブルシューティング


<a id="h-64dcc40a840e"></a>
##### 8.1. `run.ps1` が起動しない

PowerShell のエラーを確認し、次を順に実行します。

```powershell
py -3.14 --version
ffmpeg -version
```

どちらかが失敗する場合は、Python 3.14 または FFmpeg を導入し、必要な PATH を設定してから新しい PowerShell で再確認します。パッケージ導入に失敗する場合は、インターネット接続、プロキシー設定、証明書設定、ディスク空き容量を確認します。

既存の `.venv` が原因と考えられる場合は、Python と導入済みパッケージの版を記録し、運用担当者へ再作成の判断を依頼してください。仮想環境の削除はパッケージを失う操作であるため、作業中のプロセスと対象パスを確認してから行います。

<a id="h-c648cbc57cff"></a>
##### 8.2. 開始ボタンが無効になっている

起動時に FFmpeg が見つからなかった可能性があります。`ffmpeg -version` が成功することを確認し、Music DL を再起動します。

<a id="h-e0201e74bd9b"></a>
##### 8.3. URL を受け付けない

次を確認します。

1. URL が HTTP または HTTPS で始まる YouTube または `youtu.be` の URL である。
2. プレイリストの `list` パラメーターを含まない。
3. 通常動画の `watch?v=...`、短縮 URL、Shorts など、動画を特定できる URL である。
4. ブラウザーで対象動画を開ける。

形式検証を通っても、動画の存在、公開状態、地域制限、権利は事前に判定しません。

<a id="h-a37d54cba454"></a>
##### 8.4. 取得または変換に失敗する

次の順に確認します。

1. 対象動画の保存権限または許諾がある。
2. ブラウザーで動画を開け、インターネット接続が使える。
3. `ffmpeg -version` が成功する。
4. 保存先が存在し、書き込み権限と空き容量がある。
5. 詳細ログに原因を示す情報があるか確認する。
6. 検証できる環境で `yt-dlp` の更新が必要か判断する。

依存パッケージを更新する場合は、固定バージョン、変更理由、自動テスト、手動確認結果を記録します。

<a id="h-7e05a9cc27ec"></a>
##### 8.5. 設定または MP3 が見つからない

設定が保存されない場合は、プロジェクトルートへ書き込めることを確認します。保存失敗時は既存の `settings.json` を途中まで上書きせず、状態表示と詳細ログにエラーを出します。

MP3 が見つからない場合は、画面の保存先を確認し、動画タイトルに近いファイル名を探します。処理が失敗していた場合は、未完成ファイルが残っていないかも確認します。


<a id="h-4ee2d5493e7b"></a>
#### 9. 検証、受入、障害報告


<a id="h-e2331dc03633"></a>
##### 9.1. 開発時の自動確認

開発用パッケージを導入後、プロジェクトルートで実行します。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m black --check src tests
.\.venv\Scripts\python.exe -m ruff check src tests
.\.venv\Scripts\python.exe -m pyright
```

2026-08-19 時点では Python 3.14.2 で単体テスト 24 件、Black、Ruff、Pyright が成功しています。単体テストは外部サービスへ実接続せず、実際の FFmpeg 変換と GUI 操作を確認しません。

<a id="h-75f337dae8a8"></a>
##### 9.2. リリース前の手動受入

権利または許諾を確認済みの短い動画を使い、次をすべて確認します。

1. `run.ps1` から起動し、FFmpeg の確認を通過する。
2. 保存先と三つの音声ビットレートを変更できる。
3. 指定先に MP3 を生成し、再生できる。
4. 処理中も画面が応答し、二件目を開始できない。
5. 完了後に次の URL を処理できる。
6. 再起動後に保存先と音声ビットレートを復元する。
7. 空の URL、YouTube 以外、プレイリスト、到達不能な URL、無効な保存先で失敗を識別できる。
8. 取得中の終了確認で「いいえ」を選ぶと処理を継続できる。
9. FFmpeg を検出できない検証環境では、理由を表示して取得を開始できない。

FR-02 の「再生可能な MP3」と GUI の応答性は、この手動確認が完了するまで未確認です。

<a id="h-27114bd9e5a8"></a>
##### 9.3. 障害報告に含める情報

秘密情報と個人情報を除き、次を記録します。

- 発生日時とタイムゾーン
- Windows、Python、`yt-dlp`、FFmpeg のバージョン
- 実行した操作、期待した結果、実際の結果
- 状態表示と詳細ログ
