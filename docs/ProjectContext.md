# Music DL プロジェクト概要

## 1. 文書の目的

本書は、Music DL が「誰の、どの課題を、どこまで解決するか」を定義する基本文書です。
利用者、プロジェクト責任者、開発者、運用担当者を対象とし、機能の採否やリリース可否は、原則として本書の要求と受入条件に照らして判断します。

実装方法は [アーキテクチャ](Architecture.md)、導入と操作は[使い方ガイド](Usage.md) を参照してください。

## 2. 基本原則

Music DL は、利用者が保存する権利または許諾を持つ YouTube の単一動画から音声を取得し、Windows PC に MP3 ファイルとして保存するデスクトップアプリケーションです。

本プロジェクトは、次の原則を優先します。

1. URL の入力から MP3 の保存までを一つの画面で完結させる。
2. 対象を単一動画と MP3 出力に絞り、操作を分かりやすくする。
3. 入力、保存先、外部プログラムの状態を処理前に確認する。
4. 取得処理を画面処理から分離し、処理中も画面の応答性を保つ。
5. 著作権、利用規約、必要な許諾を利用者が確認したコンテンツだけを扱う。

本アプリケーションは、権利確認、利用許諾の取得、デジタル著作権管理（DRM）の回避を行いません。

## 3. 背景、目的、利用者

### 3.1. 解決する課題

YouTube 動画の音声をローカルに保存するには、通常、コマンドライン、`yt-dlp`、FFmpeg の設定が必要です。
Music DL は、URL、音質、保存先の指定と処理結果の確認を一つの画面にまとめ、これらの操作に不慣れな人でも扱えるようにします。

### 3.2. 利用者と関係者

- **主な利用者**: 権利または許諾を持つ動画の音声を、個人利用の範囲で保存する Windows 利用者
- **開発者**: 画面、設定、取得・変換処理、テストを保守する担当者
- **運用担当者**: Python、FFmpeg、Python パッケージの導入と障害の一次切り分けを行う担当者
- **外部提供者**: YouTube、`yt-dlp`、FFmpeg の提供者

### 3.3. 基本的な利用場面

利用者はアプリケーションを起動し、単一動画の URL を入力します。必要に応じて音質と保存先を変更して処理を開始し、進捗と結果を画面で確認します。
成功した場合、指定したフォルダに MP3ファイルが保存されます。

## 4. 対象範囲

### 4.1. 対象

- YouTube の単一動画 URL の入力とクリップボードからの貼り付け
- 利用可能な音声の取得と MP3 への変換
- 128、192、320 kbps からの音質選択
- 保存先フォルダの選択
- 進捗、推定残り時間、完了、失敗の画面表示
- 保存先と音質のローカル設定ファイルへの保存と復元
- 起動時の FFmpeg 確認
- 同時に一件だけを処理する制御

### 4.2. 対象外

- プレイリストまたは複数 URL の一括処理
- MP3 以外の音声形式、動画、字幕、サムネイルの保存
- 歌詞やメタデータの編集
- 処理の一時停止、再開、キャンセル、履歴管理
- 利用者認証、クラウド同期、遠隔監視
- DRM の回避、コンテンツの権利確認、利用許諾の代行

## 5. 要求事項

### 5.1. 機能要求

| ID | 要求 | 受け入れる状態 |
| --- | --- | --- |
| FR-01 | 単一動画 URL を入力できる | 手入力と貼り付けの両方を利用できる |
| FR-02 | 音声を取得し、MP3 に変換できる | 有効な対象 URL から再生可能な MP3 を生成できる |
| FR-03 | 音質を選択できる | 128、192、320 kbps のいずれかを変換処理へ渡す |
| FR-04 | 保存先を選択できる | 存在し、書き込み可能なフォルダを指定できる |
| FR-05 | 設定を復元できる | 保存先と音質を次回起動時に読み込む |
| FR-06 | 処理状況を確認できる | 進捗、完了、失敗を画面で区別できる |
| FR-07 | 重複実行を防止する | 実行中は二件目を開始しない |
| FR-08 | 対象外の入力を拒否する | 不正な URL、プレイリスト、無効な保存先を処理前に拒否する |
| FR-09 | 簡単に起動できる | `run.ps1` の一回の実行で環境確認後に起動する |

### 5.2. 非機能要求

- **対応環境**: Windows と Python 3.14 を基準とする。
- **応答性**: 取得と変換を別スレッドで実行し、画面処理を長時間止めない。
- **安全性**: 認証情報を設定やログへ保存せず、外部から得た値を信頼せずに検証する。
- **データ整合性**: 設定は検証後に扱い、一時ファイルからの置換で保存途中の破損を防ぐ。
- **信頼性**: 通信は 30 秒でタイムアウトし、通常取得と分割データ取得をそれぞれ最大 3 回
  再試行する。二重実行は防止する。
- **保守性**: 画面、取得・変換、設定、入力検証の責務を分離し、主要処理を単体テスト可能にする。
- **プライバシー**: 独自の利用分析情報は送信しない。ただし、取得時には接続先へ URL と通常の
  通信情報が送られる。
- **アクセシビリティ**: 現状はダークテーマを使用する。キーボード操作や読み上げ機能に関する
  適合基準は未定とする。

## 6. 前提条件、制約、用語

### 6.1. 前提条件と依存関係

- 利用者は対象コンテンツを保存する権利または許諾を持ち、YouTube の利用規約、著作権法、その他の適用法令を守る。
- インターネット接続、Python 3.14、`customtkinter`、`yt-dlp`、FFmpeg を利用できる。
- 保存先に書き込み権限と十分な空き容量がある。
- 対応可否は YouTube、`yt-dlp`、FFmpeg の仕様や稼働状態に影響される。
- ファイル名と同名ファイルの扱いは `yt-dlp` の動作に従う。

### 6.2. 用語

| 用語 | 説明 |
| --- | --- |
| ビットレート | 1 秒当たりの音声データ量。値が大きいほど一般に容量も増えるが、元音源以上の品質にはならない |
| FFmpeg | 取得した音声を MP3 に変換する外部プログラム |
| `yt-dlp` | 対応サイトからメディア情報や音声を取得する外部ライブラリ |
| PATH | Windows が実行プログラムを探すフォルダの一覧 |
| DRM | コンテンツの利用や複製を技術的に制御する仕組み |

## 7. 成功指標と受入条件

現段階では、次の条件をすべて満たすことを成功とします。処理時間や成功率の数値目標は、計測の仕組みがないため未設定です。

- FFmpeg が利用できる環境で、有効な対象 URL から指定先へ再生可能な MP3 を生成できる。
- 選択したビットレートが変換設定へ渡される。
- 保存先または音質の変更が設定ファイルへ保存され、再起動後に復元される。
- 空の URL、対象外 URL、プレイリスト、無効な保存先では処理を開始しない。
- FFmpeg が見つからない場合は理由を示し、処理開始を無効にする。
- 成功と失敗を画面で識別でき、実行中に二件目を開始できない。
- 取得中も画面が応答し続ける。

実サービスを使う受入試験では、権利または許諾を確認済みの短い動画を使用します。手順は[使い方ガイドの「動作確認とサポート」](Usage.md#9-動作確認とサポート) に示します。

## 8. 主な設計判断

| 採用方針 | 理由 | 代替案と主な不利益 |
| --- | --- | --- |
| Windows デスクトップ画面 | サーバーを用意せず一つの画面で操作できる | Web 画面は配布しやすいが、サーバーと認証の運用が必要になる |
| `yt-dlp` を利用 | サイト固有の取得処理を自作せずに済む | 自作は依存を減らせるが、仕様変更への追随負担が大きい |
| FFmpeg を外部導入 | 実績のある変換機能を利用できる | 同梱は導入を簡単にできるが、配布容量とライセンス管理が増える |
| JSON 形式の設定 | 人が確認・退避しやすく、追加基盤が不要 | データベースは拡張しやすいが、現規模には複雑すぎる |
| バックグラウンドスレッド | 同期式の取得処理中も画面を応答させられる | 非同期処理への全面移行は画面との統合が複雑になる |

詳細な構造と責務は [アーキテクチャ](Architecture.md) に示します。

## 9. リスクと未決事項

- URL の事前検証だけでは、動画の存在、公開状態、地域制限、利用権限を判定できない。
- 接続先のレート制限に特化した待機制御はない。
- 失敗時の一時ファイルや未完成ファイルを独自に整理する規則がない。
- 永続ログ、利用状況の計測、警告通知、自動復旧を提供していない。
- Python 3.14 と依存パッケージの互換性を更新時に確認する必要がある。
- 配布形式、コード署名、自動更新、アクセシビリティ基準、性能目標は未決である。

優先課題は、部分ファイルの扱い、依存関係の更新確認、実サービスを使う受入試験の定着です。
