## 設計方針

本アプリケーションは、画面、ダウンロード処理、設定永続化の変更影響を分離するため、
小規模なレイヤードアーキテクチャを採用します。外部サービスとファイルシステムを境界に
置き、UI にダウンロードエンジン固有の設定を持ち込まないことを基本方針とします。

## システムコンテキスト

```text
利用者
  │ URL、音質、保存先
  ▼
Music DL デスクトップアプリ
  ├── YouTube / 対応サービス ← yt-dlp による取得
  ├── FFmpeg                  ← MP3 変換
  ├── 保存先フォルダ          ← 完成ファイル
  └── settings.json           ← 保存先・音質設定
```

アプリケーションは認証情報を保持せず、サーバー側コンポーネントやデータベースを持ちません。

## レイヤーと責務

### エントリーポイント

`src/main.py` は `ModernUI` を生成し、CustomTkinter のイベントループを開始します。
起動コマンドは `python -m src.main` です。

### プレゼンテーション層

`src/ui` は画面表示と利用者操作を担当します。

- `app_window.py` の `ModernUI` は、入力、設定変更、処理開始、進捗、結果表示を統括します。
- `theme.py` の `Theme` は、色とフォントのデザイントークンを一元管理します。
- ダウンロード中は開始ボタンを無効化し、完了後に再び有効化します。
- ワーカースレッドからの通知はスレッド安全なキューへ格納し、`after()` でUIスレッドが
  取り出します。
- 詳細ログはメモリ上の画面部品に表示し、ファイルへは保存しません。

### コア層

`src/core` は UI から分離した処理を担当します。

- `download_service.py` の `DownloadService` は、FFmpeg の存在確認、`yt-dlp` の設定、
  バックグラウンドスレッドの開始、進捗と結果の通知を担当します。
- `config.py` の不変な `AppConfig` は検証済みの保存先とビットレートを保持します。
- `config.py` の `ConfigManager` は `settings.json` の読込と原子的な保存を担当します。
- `validation.py` はYouTube単一動画URLと保存先フォルダを外部入力の境界で検証します。

### 外部依存境界

- `yt-dlp`: メディア情報と音声ストリームを取得します。
- FFmpeg: `yt-dlp` の後処理として音声を MP3 へ変換します。
- ファイルシステム: 設定と出力ファイルを保存します。
- YouTube または `yt-dlp` 対応サービス: ネットワーク越しの取得元です。

## 主要データフロー

### 起動と設定読込

1. `src.main` が `ModernUI` を生成します。
2. `ConfigManager.load()` が作業ディレクトリの `settings.json` を読み込みます。
3. ファイルが存在しない、または読込に失敗した場合は、保存先を利用者ホーム配下の
   `Downloads`、ビットレートを 192 kbps とします。
4. `DownloadService.validate_environment()` が PATH 上の `ffmpeg` を確認します。
5. FFmpeg が見つからない場合は、画面に警告し、処理開始を無効化します。

### ダウンロードと変換

1. UI が URL の形式、YouTubeホスト、動画識別子、プレイリストでないことを確認します。
2. サービス層がURLと保存先を再検証し、FFmpegの存在を確認します。
3. UI が `DownloadService.run_download()` に URL、設定、3種類のコールバックを渡します。
4. サービスがロックで実行枠を確保し、デーモンスレッドで `yt-dlp` を実行します。
5. 取得中は進捗率と推定残り時間をUIイベントキューへ通知します。
6. 取得完了後、FFmpeg の MP3 変換開始を通知します。
7. 成功時は動画タイトルと完了、失敗時はURLをマスクした例外概要を通知します。
8. 最後にロック保護された実行中フラグを解除し、完了コールバックを呼び出します。

### 設定更新

1. 利用者が保存先または音質を変更します。
2. UI が `AppConfig` を更新します。
3. `ConfigManager.save()` が UTF-8 の一時JSONをフラッシュし、`settings.json` へ原子的に
   置換します。失敗した場合は一時ファイルを除去し、UIへエラーを返します。

設定形式は次のとおりです。

```json
{
  "save_dir": "C:\\Users\\user\\Downloads",
  "bitrate": "192"
}
```

## 状態と並行処理

- `ModernUI` が画面状態、現在設定、URL、ステータス表示を所有します。
- `DownloadService.is_running` がロックで保護されたプロセス内の単一実行を表します。
- ダウンロードはデーモンスレッドで実行されるため、アプリ終了時に処理完了を待ちません。
- ワーカースレッドはUI部品を直接操作せず、コールバック内容を `queue.Queue` へ格納します。
  UIスレッドが50ミリ秒間隔でキューを処理します。

## エラー処理

- FFmpeg 不在は起動時に検出し、開始ボタンを無効化します。
- ダウンロードまたは変換中の例外は `DownloadService` で捕捉し、詳細ログと失敗状態を
  UI へ通知します。
- 設定読込エラーは既定値へフォールバックします。
- 設定読込の警告は詳細ログ、設定保存エラーはステータスと詳細ログへ表示します。
- 通信タイムアウトは30秒、通常取得とフラグメント取得の再試行上限は各3回です。
- キャンセルと部分ファイルの独自削除は実装していません。

## セキュリティとデータ保護

- API キー、パスワード、Cookie をアプリケーション設定として扱いません。
- URL、外部サービス応答、動画タイトルは外部入力です。現行実装では `yt-dlp` に処理を
  委ねていますが、URL の許可方式や保存先検証は今後の強化対象です。
- `settings.json` にはローカルパスが平文で保存されます。秘密情報を保存してはいけません。
- エラーログには URL や外部ライブラリの例外文が表示される場合があります。画面共有や
  問い合わせ時は、個人情報を含まないことを確認する必要があります。
- 利用者は対象コンテンツの権利、許諾、利用規約への適合を確認する責任を負います。

## 技術スタック

| 分類 | 技術 | 用途 |
| --- | --- | --- |
| 言語 | Python 3.14 基準 | アプリケーション実装 |
| UI | CustomTkinter | デスクトップ画面 |
| 取得 | `yt-dlp` | 音声取得と FFmpeg 連携 |
| 変換 | FFmpeg | MP3 変換。OS 側の外部依存 |
| 設定 | 標準 `json`、`dataclasses` | 設定構造と永続化 |
| テスト | pytest | 単体テスト、境界値、正常系、異常系 |
| 品質 | Black、Ruff、Pyright | 整形、lint、型チェック |

実行依存関係は `requirements.txt`、開発・検証用依存関係は `requirements-dev.txt` に分離し、
検証済みバージョンを固定します。Black 24.10.0はPython 3.14上で純Python版として実行し、
整形対象構文をPython 3.13互換とします。アプリケーションとPyrightの基準はPython 3.14です。

## 設計判断と代替案

| 判断 | 採用理由 | 代替案とトレードオフ |
| --- | --- | --- |
| レイヤード構成 | 小規模でも UI と外部処理の変更を分離できる | 単一ファイルは簡単だが保守とテストが難しくなる |
| `yt-dlp` のラップ | UI を取得エンジンの詳細から分離する | UI から直接利用するとコード量は減るが結合度が上がる |
| JSON 設定 | 追加基盤なしで確認・復旧できる | Pydantic は検証を強化できるが現規模では依存が増える |
| スレッド実行 | 同期的な `yt-dlp` と UI イベントループを分離できる | `asyncio` は一貫した非同期化が必要で UI 統合が複雑になる |

## テスト戦略と受入判断

現行の単体テストは次を対象とします。

- 設定の既定値、読込、保存
- FFmpeg の存在確認
- ダウンロード成功時の `yt-dlp` 呼出しと完了通知
- 実行中の重複開始防止
- URL、プレイリスト、保存先の境界検証
- 外部処理失敗、URLマスキング、進捗計算

外部ネットワークと FFmpeg を使用する結合テスト、UI 操作テスト、失敗系の網羅、実ファイルの
再生確認は未整備です。リリース判断では、単体テストに加え、権利確認済みの短い動画を使った
手動の垂直スライステストを実施します。具体的な手順は `docs/Usage.md` を参照してください。

## 運用と障害対応

- 起動時に FFmpeg 警告が出る場合は、インストールと PATH を確認します。
- 取得に失敗した場合は詳細ログを開き、URL、ネットワーク、`yt-dlp` の更新状況、保存先の
  権限と空き容量を確認します。
- 設定が破損した場合は、アプリケーション終了後に `settings.json` を退避して再起動すると
  既定値で動作します。
- 永続ログ、メトリクス、アラート、自動復旧はありません。利用者による画面確認が基本です。
- 外部サービスの仕様変更に備え、`yt-dlp` のリリースと互換性を定期的に確認します。

## 既知のリスクと改善候補

- 設定ファイルを作業ディレクトリではなく OS の利用者別設定領域へ移す。
- キャンセルと部分ファイル処理を定義する。
- レート制限専用の待機制御を追加する。
- 構造化ログと秘密情報のマスキング方針を導入する。
- 外部 API の契約テストとUI操作テストを追加する。
