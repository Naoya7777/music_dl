# Music DL 使い方ガイド

## 1. このガイドの目的

このガイドは、Windows で Music DL を導入、起動、操作し、問題を切り分ける方法を説明します。
主な対象は利用者と導入・運用担当者です。

準備済みの環境では、プロジェクトのフォルダで次のコマンドを一回実行すれば起動できます。

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

起動後は、単一の YouTube 動画 URL を入力し、音質と保存先を確認して「MP3をダウンロード」を選びます。処理できるのは、利用者が保存する権利または許諾を持つコンテンツだけです。
サービスの目的と制約は [プロジェクト概要](ProjectContext.md)、内部構造は[アーキテクチャ](Architecture.md) を参照してください。

## 2. 利用前の確認

### 2.1. 必要な環境

- Windows
- Python 3.14 と Python Launcher の `py` コマンド
- インターネット接続
- FFmpeg と、その保存場所を登録した PATH
- 保存先への書き込み権限と十分な空き容量

FFmpeg は音声を MP3 に変換する外部プログラムです。PATH は、Windows が実行プログラムを探すフォルダの一覧です。
Python パッケージの `customtkinter` と `yt-dlp` は、`run.ps1` が必要に応じて導入します。

### 2.2. 権利と利用条件

対象コンテンツを保存する権利または必要な許諾があることを、利用者自身で確認してください。
YouTube の利用規約、著作権法、その他の適用法令を守り、無断複製やデジタル著作権管理（DRM）の回避に使用しないでください。Music DL は権利確認や許諾取得を代行しません。

## 3. 導入

### 3.1. 自動準備を使う

Python 3.14 と FFmpeg を導入した後、プロジェクトのフォルダで次を実行します。

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

`run.ps1` は次の順序で処理します。

1. `py` コマンドと FFmpeg が使えるか確認する。
2. `.venv` に仮想環境がなければ Python 3.14 で作成する。
3. `customtkinter` または `yt-dlp` を読み込めなければ、`requirements.txt` から導入する。
4. プロジェクトのフォルダを作業フォルダとして Music DL を起動する。

仮想環境とは、このプロジェクト専用の Python パッケージを他のプロジェクトから分離する仕組みです。
`-ExecutionPolicy Bypass` は、この一回の PowerShell 実行に限ってスクリプトの実行を許可する指定であり、Windows 全体の設定は変更しません。

### 3.2. 手動で準備する

自動準備を使わない場合は、プロジェクトのフォルダで次を実行します。

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

FFmpeg は信頼できる配布元から導入し、`ffmpeg.exe` のあるフォルダを PATH に追加します。
新しい PowerShell を開き、次が成功することを確認します。

```powershell
ffmpeg -version
```

Python や依存パッケージの対応状況は更新で変わる可能性があります。更新する場合は、現在のバージョンと動作確認結果を記録してください。

## 4. 起動

### 4.1. `run.ps1` から起動する

通常は、プロジェクトのフォルダで次を実行します。

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

デスクトップに「Music DL」ショートカットが設定されている PC では、ショートカットから同じ `run.ps1` を実行できます。
ショートカット自体は利用者環境の設定であり、リポジトリには含まれません。

### 4.2. 準備済みの仮想環境から直接起動する

```powershell
.\.venv\Scripts\python.exe -m src.main
```

`src/main.py` をファイルとして直接実行せず、`-m src.main` のモジュール形式を使ってください。
モジュール形式は、`src` 内の相対的な読み込み関係を正しく解決します。

## 5. 基本操作

1. YouTube の単一動画 URL を入力します。「貼り付け」ボタンも利用できます。
2. 音質を 128k、192k、320k から選びます。初期値は 192k です。
3. 「保存先」を選び、出力フォルダを指定します。初期値は利用者の `Downloads` です。
4. 「MP3をダウンロード」を選びます。
5. 状態表示、進捗バー、必要に応じて詳細ログを確認します。
6. 「MP3 の保存が完了しました」と表示されたら、保存先でファイルを確認します。

`k` は kbps（キロビット毎秒）を表し、1 秒当たりの音声データ量です。値が大きいほど一般にファイル容量も増えますが、元の音声を超える品質にはなりません。

処理中は URL、貼り付け、音質、保存先、開始ボタンを操作できません。成功後は URL 欄が空に戻り、次の一件を開始できます。

## 6. 設定、ログ、保存ファイル

### 6.1. 設定

保存先と音質は `settings.json` に保存され、次回起動時に復元されます。`run.ps1` から起動した場合は、プロジェクトのルートに作られます。

```json
{
  "save_dir": "C:\\Users\\user\\Downloads",
  "bitrate": "192"
}
```

このファイルへ秘密情報を書かないでください。設定が壊れた場合は既定値が使われ、詳細ログに警告が表示されます。
手動で初期化する場合は、アプリを終了し、`settings.json` を別名で退避してから再起動します。以前の保存先と音質は自動では戻りません。

### 6.2. 詳細ログ

「詳細ログを表示」を選ぶと、環境確認、設定変更、処理開始、完了、失敗を確認できます。
ログは画面内だけにあり、ファイルには保存されません。アプリを終了すると消えます。

エラー中の URL は `[URL]` に置き換えて表示します。ただし、ファイル名や環境情報が含まれる可能性があるため、問い合わせや画面共有の前に公開してよい内容か確認してください。

### 6.3. MP3 ファイル

MP3 は画面で指定したフォルダへ保存されます。ファイル名は動画タイトルを基に `yt-dlp` が作ります。Windows で使えない文字の変換や同名ファイルの扱いも `yt-dlp` の動作に従います。

## 7. 利用上の制約

- 一回に処理できる URL は一件です。
- YouTube の単一動画だけを受け付け、プレイリストや YouTube 以外の URL は拒否します。
- 出力形式は MP3 だけです。
- 一時停止、再開、キャンセル、履歴管理はありません。
- 取得可否は、動画の公開状態、地域制限、ネットワーク、YouTube、`yt-dlp`、FFmpeg に依存します。
- 通信は 30 秒でタイムアウトし、通常取得と分割データ取得をそれぞれ最大 3 回再試行します。
- 取得中にアプリを終了すると、処理完了を保証できません。終了確認で「いいえ」を選び、処理完了を待ってください。
- 失敗時の一時ファイルや未完成ファイルを自動で整理する独自機能はありません。

## 8. トラブルシューティング

### 8.1. `run.ps1` が起動しない

PowerShell で表示された内容を確認し、次を順に実行します。

```powershell
py -3.14 --version
ffmpeg -version
```

どちらかが失敗する場合は、Python 3.14 または FFmpeg を導入し、必要な PATH を設定してから新しい PowerShell で再確認します。
パッケージ導入に失敗する場合は、インターネット接続とプロキシー設定、ディスク空き容量を確認します。

### 8.2. 開始ボタンが無効になっている

起動時に FFmpeg が見つからなかった可能性があります。`ffmpeg -version` が成功することを確認し、Music DL を再起動してください。

### 8.3. 取得または変換に失敗する

次の順に確認します。

1. URL が空でなく、ブラウザーで対象動画を開ける。
2. YouTube の単一動画 URL であり、プレイリストの `list` パラメーターを含まない。
3. 対象動画の保存権限または許諾がある。
4. インターネット接続が使える。
5. 保存先が存在し、書き込み権限と空き容量がある。
6. 詳細ログに原因を示す情報がないか確認する。
7. 検証できる環境で `yt-dlp` の更新が必要か確認する。

### 8.4. 設定が保存されない

プロジェクトのフォルダに書き込めることを確認します。保存に失敗した場合、状態表示と詳細ログにエラーが出ます。既存の `settings.json` は途中まで上書きされません。

### 8.5. MP3 が見つからない

画面の保存先を確認し、動画タイトルに近いファイル名を探します。処理が失敗していた場合は、未完成ファイルが残っていないかも確認してください。

## 9. 動作確認とサポート

### 9.1. 開発時の自動確認

開発用パッケージを導入後、プロジェクトのフォルダで実行します。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m black --check src tests
.\.venv\Scripts\python.exe -m ruff check src tests
.\.venv\Scripts\python.exe -m pyright
```

単体テストでは、外部サービスへの実接続や実際の MP3 変換を行いません。

### 9.2. リリース前の手動確認

権利または許諾を確認済みの短い動画を使い、次をすべて確認します。

1. 起動し、FFmpeg の確認を通過する。
2. 保存先と三つの音質を変更できる。
3. 指定先に MP3 を生成し、再生できる。
4. 処理中も画面が応答し、二件目を開始できない。
5. 完了後に次の URL を処理できる。
6. 再起動後に保存先と音質を復元する。
7. 空の URL、対象外 URL、プレイリスト、到達不能な URL で失敗を識別できる。

### 9.3. 障害報告に含める情報

秘密情報と個人情報を除き、次を記録します。

- 発生日時とタイムゾーン
- Windows、Python、`yt-dlp`、FFmpeg のバージョン
- 実行した操作、期待した結果、実際の結果
- 画面表示と詳細ログ
- 保存先の権限と空き容量
- 同じ操作で再現するかどうか
